# 课后作业离线提取

从浏览器保存的超星 / 学习通 `.mhtml`、`.mht` 文件中提取作业题目，生成 UTF-8 Markdown，并把题图和公式图片保存在本地。含加密文字的题目先按归档字体渲染，再整题交给本地 **PP-OCRv4 mobile** 识别；不使用字形映射、识别缓存或人工审核流程。

支持章节练习页面及新版独立作业编辑页（如 `数电第二章2.mhtml`）。新版页面的选择题选中状态和计算题编辑框属于学生作答，不作为正确答案导出；保存的页面若没有官方答案与解析，仍需使用后续 AI 解答与纠错流程。

## 运行

需要 Windows、64 位 Python 3.10 或以上版本。在本项目目录执行：

```powershell
python -m pip install -r requirements.txt
python -B -X utf8 extract_homework.py "新的页面.mhtml"
```

批量提取文件夹第一层中的所有 `.mhtml` / `.mht` 文件：

```powershell
python -B -X utf8 extract_homework.py . -o exports/run_ocr
```

也可以一次指定多个文件：

```powershell
python -B -X utf8 extract_homework.py "页面1.mhtml" "页面2.mhtml" -o exports/new_batch
```

每个文件导出为 `<输出根目录>/<源文件名>/questions.md`、`questions.json` 和 `images/`。Markdown 中使用 `images/...` 相对路径；移动资料时请带上整个文件夹。JSON 保存题目、选项、填空数量、导出提示、本次 OCR 模型和整题图片数量。`ocr_images/question_001.png` 等文件保留真正送入 OCR 的题目图片，编号对应整份文档的连续题号；题目的 `ocr_image` 字段指向对应图片。

默认使用 v4，也可通过 CLI 对比保留的 v6 tiny 模型：

```powershell
python -B -X utf8 extract_homework.py "学生学习页面.mhtml" -o exports/v6_compare --ocr-model v6tiny
```

## Qt 界面

```powershell
python -B -X utf8 homework_gui.py
```

默认扫描启动时的当前文件夹；也可以指定文件夹，例如 `python -B -X utf8 homework_gui.py "保存的页面"`。界面左侧显示 MHTML 文件列表和数量，顶部可刷新或选择其他文件夹。

也可以右键项目根目录的 [`start.ps1`](start.ps1)，选择“使用 PowerShell 运行”。脚本自动从项目目录启动，但**不会自动安装 Python 或依赖**。首次克隆后，需要先在 Windows 上安装 64 位 Python 3.10 或以上版本，并用启动脚本将使用的同一个 Python 安装 [`requirements.txt`](requirements.txt) 中的依赖；即使暂不使用 API，也需要安装 OpenAI SDK，因为界面启动时会导入请求模块。

如使用虚拟环境，须先激活环境，再从该 PowerShell 窗口运行脚本，避免右键启动时选到全局 Python：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
.\start.ps1
```

脚本执行受策略限制时，可以在已安装好依赖的同一环境中运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1`，无需修改系统的全局执行策略。

仓库包含离线预览资源、字体、OCR DLL 和两套模型，不需要被忽略的本地 SDK 目录、历史导出、API 配置或界面状态才能启动。首次启动没有作业文件时会显示空列表，请自行提供网页归档或在界面中选择存放作业的文件夹。API 配置需在界面中重新填写，界面状态和导出目录会在使用时自动创建。生成题目图片还需要本机 Edge / Chrome；没有这些浏览器时，执行 `python -m playwright install chromium` 安装渲染浏览器。

右侧依次为“资料制作”“纠错补充”和“复习提问”三个栏目，标签显示在标题下方。文件标题、底部状态和运行日志始终可见。

选中 MHTML 文件后，右侧顶部标题只显示文件名主体，不显示 `.mhtml` 或 `.mht`。点击标题可原位编辑，按“确定”或回车重命名，按 Esc 取消；直接输入新名称会沿用原来的扩展名。同名文件不会被覆盖。已有导出和图片仍关联到重命名后的文件；再次转换会按新文件名生成新版导出。

“复制提示词”右侧可以选择提示词模板，再点“设置提示词”管理：左侧选择、添加或删除模板，右侧编辑名称和解题要求；切换条目保留草稿，点击“保存”写入 `data/prompt_templates.json`，取消则放弃修改。原有解题提示词保存为“模电”，另有针对逻辑函数、卡诺图和真值表的“数电”模板。题号映射、分题起止标记及公式输出要求由程序自动附加，无需在模板中手写。公式要求使用 Markdown LaTeX（`$...$`、`$$...$$`），例如 `$\overline{C}\,\overline{D}$`，避免用组合横线等 Unicode 特殊字符拼接公式。

复制提示词和“直接调用 API”使用同一个选中模板；模板选择在所有文件间共用，重启后恢复。API 请求发起时保存提示词快照，重试仍使用上次的提示词，即使之后切换或修改了模板。纠错提示词也包含相同的 LaTeX 公式要求。

右上角的“API 配置”可添加多个模型配置，左侧列表支持添加和删除。右侧依次为展示名称、Base URL、API Key、模型 ID，再设置 Temperature、Top P、最大输出 Token、连接 / 读取超时、流式返回、是否发送题图、系统提示词和额外请求参数。模型 ID 默认选择“使用自定义模型id”，下方显示自定义输入行，已有配置的模型 ID 会保留在这里。填写地址和密钥后，点击模型下拉框右侧的“获取模型列表”，即可在后台只读查询服务商模型目录，无需先填模型 ID，不发送题目或创建生成请求。获取成功后更新下拉选项、去除重复项，并始终在最后保留“使用自定义模型id”；当前模型若在列表中会自动选中，否则保留自定义值。选择目录中的模型时隐藏自定义输入行，切回自定义项则重新显示并保留输入。接口不支持模型列表、返回空列表或查询失败时仍可手动填写。切换配置会保留当前编辑会话的列表与选择；修改地址或密钥会清除旧列表并保留当前模型 ID，避免使用其他服务商的过期结果。编辑过程中可切换条目保留草稿，点击“保存”才写入；“取消”放弃本次改动。Base URL 填写服务商提供的完整前缀或完整的聊天补全地址。最大输出 Token 设为 0 时不发送该参数；服务商特有的参数可填写在额外请求参数中。模型列表查询实现见 [`api_models.py`](api_models.py)。

配置以明文保存在 `data/api_config.json`，API Key 默认在界面中遮盖，勾选“显示”可查看。`.gitignore` 排除此配置、保存时的临时文件、解答输入临时文件和保存草稿的 `data/gui_state.json`。本地 SDK 依赖、Python 缓存及虚拟环境、`exports/` 导出结果和可能包含个人信息的 `.mhtml` / `.mht` 网页归档也不纳入版本控制；这些文件仍保留在本地，克隆项目后需自行提供测试所用的网页归档。源码、测试、提示词模板、离线预览资源及 OCR DLL / 模型保留在版本控制范围内。下拉框中的 API 选择在所有作业间共用，并保存于 `data/gui_state.json` 的 `selected_api`；该文件保存配置 ID 和输入草稿，不保存 Key。

题目卡片下方左侧是“粘贴 AI 的 Markdown 解答”和输入框，右侧独立显示 API 选择、调用按钮及思考强度。输入框按题目卡片分别保存草稿；从第 1–6 题切到第 7–10 题会显示后一张卡片的内容，切回来可继续编辑原草稿，重启后也会恢复。旧版按文件保存的一份输入会归到首次选中的卡片。先生成图片并选中一张卡片，再选 API 并点击“直接调用 API”：后台通过 `api_homework.py` 发送这一张卡片对应的题目、现有分题提示词及题图。旁边的“重试请求”会再次发送上一次卡片的请求，沿用当时选择的 API 与思考档位；切换到另一份作业或重新生成导出后不可重试旧请求。题图原始文件转为 Base64 data URL 后随请求发送，无需先上传到图床；开启发送题图时，需要所选模型支持图片。关闭发送题图时只发送题目文字，模型无法读取本地图片链接。

API 请求期间可以切换卡片并在其他题组的输入框粘贴解答。正在由 API 解答的题组输入框会锁定，流式回复只更新该题组。其他题组的输入和整理任务会保留并在请求结束后处理；即使其他输入框粘贴了相同题号的解答，这次整理也会跳过 API 占用的题号，保留 API 结果。

思考强度行是本次请求的“思考”选择。选定模型后，界面会在后台用该配置的 Base URL、API Key 和模型 ID 只读查询模型目录；阿里云兼容地址还会尝试同一主机的扩展模型目录。自动查询不会发送题目或创建付费解答请求。若目录缺少档位，显示“档位未提供”，不代表模型不支持思考。点击“重试获取思考强度”会重新查询目录；目录仍未提供档位时，通过一次仅要求回复 OK、最多输出 16 tokens 的最小请求探测关闭思考参数，不发送题目、题图或保存的额外参数，可能产生少量 API 费用。只有服务端明确返回包含当前模型 ID 的专属可用档位列表时，才据此筛选下拉框；通用参数枚举、请求成功或失败本身都不视为档位已确认，也不代表已逐档验证生成效果。目录明确提供档位时不额外探测。重试保留仍可用的已选档位，纠错页同步这些选项。始终无法确认时仍可手动选择，以服务端实际响应为准。手动选择的档位只影响当前请求：覆盖该配置中的思考开关、预算和思考参数；选“默认”则继续使用模型配置或服务端默认值。Temperature 不随思考档位自动改变。流式接口返回思考过程时，界面显示累计长度，但只把正式解答写入 Markdown 输入框。相关实现见 [`api_reasoning.py`](api_reasoning.py)。

接口通过官方 OpenAI Python SDK 调用兼容 Chat Completions 的 `POST /chat/completions`，请求格式参考 [阿里云兼容接口文档](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions)。模型目录查询也使用同一个 SDK；请求层不再使用 `urllib`。本程序暂不支持服务商自有的其他协议。流式返回时在输入框中实时显示解答，输入框暂时只读；按钮变为“停止请求”。完整返回且包含当前卡片所有题目的正确标记时，才自动调用现有解答整理 CLI 并更新整理文档。网络错误、超时、截断和主动停止不会导入半截答案，原输入会恢复；已完整返回但标记缺失的解答留在输入框供手动修正，不会自动导入。SDK 自动重试关闭，并禁止跟随重定向。点击停止只中止本地等待，服务端是否继续计算或计费由服务商决定。

如果服务商返回 Cloudflare 1010，状态栏会明确显示客户端被服务商安全策略拦截，并附上 Ray ID。本程序已采用服务商调用示例使用的官方 SDK；如果仍被拦截，可把错误码和 Ray ID 提供给服务商排查。

`tests/probe_api_sdk.py` 是需要手动运行的真实接口测试，不参与自动测试。它从本地配置读取 Key，分别运行服务商示例中的 Chat Completions、Responses 和模型目录请求，不会把 Key 写入脚本或输出。Responses 仅用于此诊断测试，作业解答仍使用 Chat Completions。诊断安装的 SDK 可位于 `data/sdk_packages/`，正常部署通过 `requirements.txt` 安装依赖。

```powershell
python -B -X utf8 tests/probe_api_sdk.py --protocol all
```

界面使用固定浅色配色，不随 Windows 深色主题改变控件背景。下拉菜单采用白底深色文字、蓝底白字选中项；单选按钮以空心圆和蓝色圆点区分状态，收藏复选框显示白色勾选标记。输入框、数字框、右键菜单和禁用控件也使用明确的文字与背景颜色。

选择文件后，“资料制作”中可转换成 Markdown、打开 Markdown 或其所在文件夹。已有导出会直接显示题数和图片卡片；再次转换会生成新版本，保留原来的文件。输入框右上角已移除“复制文字”。

“开始转换成 Markdown”右侧提供 OCR 模型下拉框，可选 **v4** 或 **v6 tiny**，默认 v4。选择在所有文件之间共用并在重启后恢复；转换过程中暂时禁用，避免改变正在运行任务的模型。

图片支持两种分组方式：按每页题数，或按最大图片高度。点击“生成图片”后，程序通过现有 CLI 在后台执行；完成后显示横向缩略图卡片。点击卡片的文字区域只选中题组，点击缩略图才把完整图片复制到剪贴板，可在聊天窗口粘贴。

底部显示实时阶段和进度条：转换时显示正在提取或 OCR 的连续题号及已处理题数；按最大高度分组时显示逐题排版测量进度，然后显示生成的图片数量及当前图片覆盖的题号。进度条的数量和百分比对应当前阶段；读取文件、启动浏览器、保存输出及关闭浏览器时显示明确的状态说明。任务完成或失败后恢复普通状态提示。

两个 CLI 的 `--progress-json` 参数会立即输出带 `@@PROGRESS ` 前缀的 JSON 进度行，供界面接收；未传参数时保留原来的终端输出。进度源于实际题目处理、排版测量和图片保存，不按时间估算。

导入网页版 AI 的解答：

1. 选中要解答的卡片，点击卡片列表右上方的“复制提示词”，粘贴到千问聊天输入框。
2. 再点击同一张卡片的缩略图复制题图，粘贴到聊天输入框，一起发送。切换卡片时需要重新复制对应提示词。
3. 使用网页的复制按钮取得回复的完整 Markdown，粘贴到下方大输入框。停止输入约 0.8 秒后，程序自动调用解答整理 CLI。
4. 识别出的解答插入每道原题后，累计生成 `questions_with_answers.md`；点击输入框下方的“打开整理后的文档”查看。卡片和输入框上方显示已导入的题数。

下一批可以全选替换输入框内容，先前导入的解答仍保存在 `answers.json` 中。同一题再次导入会更新其解答；清空输入框不会删除已有解答。尚未导入的题目仍保留在大文档中并标注状态，题图引用原来的本地 `images/`，原 `questions.md` 保留。

提示词包含“文件标识＋整份资料连续题号”的起始和结束标记，避免跨作业原题号重复导致错配。没有标记时不会猜测题号；标记重复、属于其他文件、结束标记缺失或不匹配时，本次回复不会导入，已有解答保留。数学公式、表格和代码块保留为 Markdown；公式的显示取决于所用 Markdown 查看器是否支持 LaTeX。程序支持整理手动粘贴或 API 返回的回复，不连接聊天网站。

每页题数、最大图片高度、图片宽度和分组方式是所有作业共用的设置，切换文件或扫描文件夹时保持不变，重启后恢复。`data/gui_state.json` 的 `render_settings` 保存这套全局设置；首次升级沿用上次选中文件的旧设置。每份文件的输入内容和最新输出位置仍分别保存在该文件的记录中。转换的新版本位于 `exports/ui_runs/`，图片的新版本位于对应导出目录的 `render_runs/`。界面通过后台进程调用 `extract_homework.py`、`render_homework.py`、`answers_homework.py`，不在界面内重复实现提取、渲染或解答拆分逻辑。解答按导出版本保存；重新转换产生新版本时，旧版本的整理文档仍保留在原文件夹。

“复习提问”左侧按整份资料的连续序号列出“第 X 题”；有解答时会在题号后显示结论，并按卡片宽度省略。每张卡片右侧可点星号收藏，并支持只看收藏。收藏写入当前导出文件夹的 `review.json`，下次打开仍保留。右侧显示选中题目的题干、选项、题图和解答；有修正答案时只显示修正答案。下面提供“上一题”“下一题”和“复制到 Cherry Studio”。收藏筛选开启时，翻题在筛选后的列表内移动。

“纠错补充”是第二个标签页，左侧保留同样的题号与结论列表，不提供收藏；右侧显示题目和已有 AI 解答，再输入平台的官方答案与简短解析。可复制当前单题图片或纠错提示词、粘贴综合修正解析，也可选择已有 API 配置与思考强度直接请求或重试。提示词要求对照官方简析与已有 AI 解答，以官方答案为最终结论，保留正确推导、指出错误并补全步骤。官方信息和修正解析分别保存在当前导出目录的 `review.json`，原有 AI 解答仍保留；修正解析的结论优先显示在题卡。单题图片按需生成并缓存在 `review_images/`。API 请求在独立进程中运行，当前题的修正输入暂时锁定，切换到其他题仍可编辑；返回结果只写回发起请求的题目。该标签页不显示收藏和“复制到 Cherry Studio”。

“复习提问”不显示纠错输入；有修正答案时，预览和复制内容均使用修正答案，原解答只在“纠错补充”中保留供对照。切换回该标签页时，题卡会读取最新保存的结论。

“资料制作”中的模型和思考强度下拉框均随右侧 API 区宽度伸缩；“纠错补充”页沿用同一套 API 配置，仍可单独选择本次请求的思考档位。

“复制到 Cherry Studio”通过 `review_homework.py copy` 复制当前题目和正在显示的解答的 Markdown 文字，保留公式，题图链接转换为本地文件的完整 URL。粘贴文字不会自动上传题图：需要模型看图时，在预览中的图片上右键选择“复制题图”，再到 Cherry Studio 粘贴，或手动上传原图。题图复制使用 Qt 原生剪贴板操作。

预览基于开源 [markdown-it](https://github.com/markdown-it/markdown-it)、[markdown-it-texmath](https://github.com/goessner/markdown-it-texmath) 和 [KaTeX](https://github.com/KaTeX/KaTeX)，嵌入 Qt WebEngine，支持表格、代码块、上下标和 LaTeX 公式。资源、字体和许可证均随项目保存于 `data/preview/`，无需联网，详情见 [预览资源说明](data/preview/README.md)。

复习时仍可复制到 Cherry Studio；本程序的 API 调用用于资料制作中的选中卡片，不额外添加聊天区。

解答部分也可独立使用 CLI：

```powershell
python -B -X utf8 answers_homework.py prompt "exports/学生学习页面3" --first 1 --last 5
python -B -X utf8 answers_homework.py merge "exports/学生学习页面3" --input "回复.md"
```

`prompt` 输出可直接复制的提示词，`merge` 读取 UTF-8 Markdown 回复，输出 JSON 导入结果，并更新同一导出文件夹内的解答记录和整理文档。完整回复验证通过后才会更新记录；对应题目标识必须匹配。

## 每 n 题生成一张图片

对已有导出运行独立脚本，默认每 5 道题拼成一张 PNG 长图：

```powershell
python -B -X utf8 render_homework.py exports -n 5
```

单独处理一份导出，或调整每张题数和图片宽度：

```powershell
python -B -X utf8 render_homework.py "exports/学生学习页面2" -n 10 --width 1440
```

按实际图片高度分组，尽量控制在 2400 像素以内：

```powershell
python -B -X utf8 render_homework.py "exports/学生学习页面3" --max-height 2400 -o exports/height_run
```

`--max-height` 覆盖 `-n`。程序逐题测量浏览器排版后的真实高度，按顺序放入能容纳的整题；单题本身超过上限时单独输出，保持完整。高度包括页眉、题干、选项和题图。清单中的 `oversize` 标记超高单题。

也可以在提取 MHTML 时同时渲染：

```powershell
python -B -X utf8 extract_homework.py . -o exports/new_batch --render-every 5
```

渲染脚本读取 `questions.json` 中的题干、选项、填空数和本地图片引用。按文件中的题目顺序分组，每组最多 n 题，最后不足 n 题也会输出；跨作业时保留作业标题和原题号。一道题包含的全部内容会放在同一张图中。加粗、上下标、换行和题图通过浏览器完整排版，宽图自动缩小到正文宽度，小型公式图片保留在行内。原导出针对该题的缺图或题型提示也会显示。

结果保存到每份导出目录的 `rendered/`：

```text
rendered/
  batch_001_q001-005.png
  batch_002_q006-010.png
  ...
  manifest.json
```

文件名中的题号表示整份导出的连续顺序；图片中仍保留各作业的原题号。`manifest.json` 记录每张图的题目、尺寸及原导出提示，方便按批次提交给 AI。已有渲染目录不会被覆盖；更换 n 重跑时可指定新输出根目录，例如 `-o exports/render_n10`。原 Markdown 和题图不受影响。

渲染需要本机 Edge 或 Chrome；程序自动选择已有浏览器并在后台运行，无需登录。若两者都没有，可执行 `python -m playwright install chromium`。安装好依赖及浏览器后，渲染过程不需要联网。

已有同名输出目录时会拒绝覆盖，请换一个 `-o` 目录。文件导出失败时不保留半成品；批量任务继续处理其余文件，有失败则退出码为 1。输出目录继承父目录权限，无需管理员身份运行。

## 处理流程

1. 读取 MHTML 的 HTML、CSS、字体和图片资源，找到内嵌的作业页面。
2. 读取每个内嵌页面的 `font-cxsecret` 字体，仅用它绘制页面文字，不建立“编码 → 汉字”转换表。
3. 读取题干、选项、填空数和原图片的位置。普通文字直接提取，含加密文字的题目使用 Pillow 排版成一张图片，题图也绘入其中。
4. 每道需要 OCR 的题目整张图片只调用一次 `ocr/ocr.dll` 内存 BGR 接口，默认使用 v4 mobile 检测和识别模型。
5. 按文字区域的位置取回题干与选项，直接采用 OCR 返回的文字，不逐字对齐，也不补识别单字。图片与公式图片保留原文件引用；显式填空下划线与 LaTeX 保留源文本。
6. 保存 OCR 输入图片、Markdown、JSON 和本地题图。失败时清理临时导出目录，保留已有笔记。

批量任务共享一个 OCR 引擎，只在遇到需要识别的题目时加载模型。每次重新转换都会重新渲染并识别，不读写 `font_map.json` 或 `ocr_cache.json`。短选项也放在完整题目图片中，附有“题干”“选项”标签帮助检测；这些标签会从识别结果中去掉。无法识别时明确报错，没有审核目录或逐字回退。

整题 OCR 的结果会受上下文影响，实测可能漏字或混淆 Ω/Q、μ/u、字母和标点，不能保证与原题逐字一致。可对照 `ocr_images/` 中的输入图片核对关键数值、单位和条件。渲染出的文字使用归档字体本身，因此这些图片也可用于查看原题。

这一步导出题目，尚未调用 AI 生成解答。没有加载的题目、缺失的字体或未保存的图片无法从归档中恢复。图片缺失会在题目和导出提示中标注；公式图片缺失时保留其附带的 LaTeX。题目按页面显示顺序导出，保留显示选项编号和实际填空数。
